# One rich brief: independent local creation

Recorded 7 October 2026. This tests the updated portable skill on a different
person and world, rather than recoloring the existing starter. It is one bounded
local trial, not a benchmark or a recorded Claude Code invocation.

## Input and isolation

An independent agent received the copied `build-personal-world` folder, two
fictional published records and this initiating brief:

> Make a compact futuristic city grown around a clearing for Mira Sol, an urban
> designer and field writer. Use the supplied fictional content.json, with clear
> demo labeling. It should feel warm, curious and precise, with ceramic, planted
> terraces and frosted glass rather than cyberpunk neon. Visitors should explore
> my work, notice shared topics and inspect the project's actual supplied stages,
> with readable links and easy local content updates. Use plain HTML/CSS/JavaScript;
> no accounts, paid services or external assets. Implement a coherent small working
> portfolio and show how I edit it. It must work on a phone and have a readable path
> if graphics fail.

The supplied Civic Canopy project had Observe, Prototype and Reflect stages.
Night Traces was a field-note journal. Their supplied tags shared `public space`.
There were no real photos, measurements, contact details or CV facts to invent.

The agent could use the installed Three.js 0.186.1 dependency, but could not read
the starter's application source, previous research or intended answer. It wrote
to a separate temporary workspace. The skill copy stayed frozen; a later narrow
scope clarification in the canonical entrypoint received a separate review.

## Actual output

The result is a warm ceramic city miniature with a sectional project workshop
and a distinct field-note archive. Selecting Civic Canopy opens readable content
immediately; its three plates and tabs select the exact supplied stage text.
Real tags filter the index and highlight matching buildings. A local read-only
Node server supplies complete ordinary HTML work pages and reads validated JSON
on each request. Design palette/placement and personal records are separate files.

The trial used newly authored procedural geometry and system fonts. Both vendored
Three.js modules and the full MIT notice matched the allowed dependency by hash.
The local artifact and browser captures were retained separately; no trial code,
fictional city records or screenshots were added to the public starter package.

## Evidence and revisions

The implementation agent reported ten passing checks covering supplied records,
publication/empty states, unsafe links/duplicate IDs, stable placement, dependency
notices, actual HTTP routes/assets, fixture edits, draft exclusion, inert markup
and explicit invalid-content failure. HTTP mutations used a separate fixture.

Parent browser checks at 1280 × 720 and 390 × 844 exercised stage selection,
topic filtering, Escape focus return, work A → B → Back, Pause/Resume and keyboard
stage navigation. No horizontal document overflow occurred. Two successive paused
captures were pixel-identical. The explicit graphics-disabled path remained
readable. Reloading the project URL returned all stages with zero scripts/canvases.

A live JSON addition produced a third archive and its own ordinary reader on
reload without a build. The two existing visible label rectangles were exactly
unchanged. The original JSON was restored byte for byte. This tests addition on
reload, not incremental updates to an already mounted scene.

Source review led to history, lifecycle, paused retargeting and topic/stage-color
corrections. Parent rendering identified a removed shadow-map option; the agent
used the supported r186 option. A final rendered reload had no new warnings or
errors. This was one initiating brief followed by review and revisions, not an
unattended first attempt or an instant result.

## Practical limits

The result is a functional illustrated miniature, not cinematic realism or proof
of superior design. Stable generated positions can crowd; additional entries may
need placement overrides. The local workflow has no hosted CMS or deployment.
The graphics-disabled switch and discrete-motion mode were exercised; actual GPU
context loss and OS preference changes were not induced. Physical phones, touch,
assistive technology, frame timing, memory and battery were not measured.

This shows that the supplied skill can inform a distinct implemented local
portfolio. It does not prove automatic skill discovery in another host, a general
world-plugin API, or that every prompt will produce equivalent quality.
