# Personal Worlds: distinction and traction strategy

Research date: **2026-10-06**. This is a product recommendation based on primary-source comparisons and the current source. Proposed features below are not shipped, globally new inventions, or promises of stars. The supporting [competitive landscape](competitive-landscape-2026-10-06.md), [product options](differentiation-options-2026-10-06.md) and [traction evidence](traction-evidence-2026-10-06.md) record the detailed sources and limits.

## Recommendation

**Make the work shape the world, then make the first successful adaptation easy.** Personal Worlds currently offers three authored environments, a portable design workflow, readable entries and local validated JSON refresh. Its scene still receives five collection destinations: adding a paper changes the reading view, rather than creating a meaningful object. This is the most consequential gap between the current demonstration and a useful reusable portfolio system.

The proposed pitch to earn is: **“Turn your work into a world you can keep updating.”** The current accurate pitch remains a free agent skill and Three.js starter for personal portfolio worlds. Do not present content-derived objects, entry routes, a browser editor or hosted CMS as current features.

The comparison is bounded. Public availability does not grant reuse permission; no comparator code, media or wording was incorporated during this search. ORBIT's actual commercial license was retrieved in this pass, resolving the previous retrieval uncertainty. This is inspection, not authorization to reuse it.

The live [OpenVGAL builder](https://openvgal.com/create) and [GalaxyBrain demo](https://galaxybrain.netlify.app/) were also inspected in the browser. OpenVGAL presents scene-style previews and a clear folder-to-room starting action before generation. GalaxyBrain opens with a central “Start Here” graph cue; interacting with that node exposed a Welcome title and note preview. Full note navigation, gallery export, mobile behavior and performance were not verified in this pass. No competitor screenshots or assets were saved into this release. The practical design lesson is a clear first authoring action and understandable entry labels, rather than expecting a visitor to decode an abstract graph unaided.

## The first change to build

Create one bounded entry-level atlas in **sea and orbital**, using clearly labeled example data first. Keep the five categories as an overview. A selected category exposes a few published entries, each with a stable ID and position, a title and an inspectable object. Each object immediately opens its readable entry; movement never gates reading.

Demonstrate one small sequence:

1. Add a project record to the content file.
2. Refresh: its object appears, and its title is readable.
3. Open the object or its ordinary URL: both resolve to the same entry.
4. Edit the title: the object and page update without resetting other positions or losing focus.
5. Hide the record: it disappears from objects, reading, relations and public exports.

Only owner-authored relationships should claim connections such as “implementation,” “field note” or “follow-up.” Shared tags can filter; they should not invent scientific relationships. Bound the number of visible objects and offer search/list access for the rest. Preserve empty collections, keyboard access, Pause, reduced motion and a complete reading path when WebGL fails.

For Orestis' sea, a paper object could reveal its genuine main figure, explanation and source. A separate small interactive instrument could explain a supplied mechanism, with clear limits. The existing interference field is illustrative and must not be relabeled as a SIGS or Sim2Science result. For a second portfolio, an architect's section control or a photographer's contact-sheet interaction would demonstrate different personal mechanics. These are proposed examples, not generated or scientifically validated work.

The useful proof is **one content edit changes a meaningful world object and an ordinary page**, across two settings. After that, add a narrow account-free import/edit/export desk or a tested free content provider. Distinguish local edits from production publishing. A full editor, extra themes, game physics and higher-end water can wait until real users reveal which matters.

## What would make the skill credible

Record an actual invocation and a complete second adaptation, with the host/version, brief, output and human revisions stated plainly. The current 45-second movie demonstrates the starter and a prompt example; it does not demonstrate an agent executing that prompt. A clearly illustrative second brief can prove the method's rendered behavior; a later independent user's completed portfolio is stronger adoption evidence.

A second world should differ in its objects, layout and at least one useful interaction, not only color. Its conventional reading version should also look intentional. Verify the installation and host loading that are advertised. The existing brief-generation test and format checks are useful but do not establish live Claude Code execution.

## X launch, with no paid platform requirement

The user will post manually. A [15-second teaser](../assets/personal-worlds-x-teaser.mp4) uses the actual captured starter: keyboard boat travel, the field, orbital, woodland and the repo end card. It starts with motion; the [45-second tour](../assets/personal-worlds-demo.mp4) remains the fuller explanation. Both are silent and captioned. Current [X help](https://help.x.com/en/using-x/x-videos) allows non-Premium video uploads up to 140 seconds and 512 MB; both cuts are comfortably below those limits. A successful X upload was not tested.

Use one short post with the native video and a useful invitation. Link the repo, where the live demo is the first action. Avoid untested claims such as “first,” “live CMS,” “photorealistic” or guaranteed unique output. An optional reply can explain the local JSON/static-host boundary and link the full demo. A later post should show the meaningful content update or a different adaptation, rather than repeat the same announcement.

Suggested current draft (for the human to adapt):

> I'm building Personal Worlds: a free agent skill + Three.js starter for portfolios that feel like places.
>
> Three worlds, readable work and local content updates.
>
> Try it / make it yours: https://github.com/oroikono/personal-worlds

This is a presentation experiment, not a claim about X's ranking algorithm. One clear request for feedback is better research than an appeal for coordinated stars. Replies can ask what prevented someone from making the demo their own.

## Release and distribution order

**Now:** share the current work in progress on X with the truthful clip; keep the repository's demo/template/skill paths obvious. API inspection confirms the public repo is an MIT-recognized template, its homepage is the live Pages demo, and it has relevant topics. At inspection it had zero stars, forks and open issues. That is a starting snapshot, not a verdict on usefulness. No repository settings were changed.

**Next:** build the single entry-object experiment and a second substantially different adaptation; test a first content edit with several willing independent users. Public discovery passed with the official `skills@1.7.1` CLI's `--list` mode in a temporary project with telemetry disabled: it found `build-personal-world`. GitHub inspection also confirmed the canonical skill and its three references. Installation, reference copying and actual host invocation still need tests before advertising full compatibility. [skills.sh](https://www.skills.sh/docs) is relevant distribution for this format, but a directory listing or installation count is not proof of successful use.

**Then:** publish a small tagged release and a technical Three.js Showcase if the human chooses, following its [moderation rules](https://discourse.threejs.org/guidelines). A later Show HN or Reddit submission needs eligibility and human-written text under their current rules; details are in the traction report. A free [Hugging Face Static Space](https://huggingface.co/docs/hub/en/spaces-sdks-static) is feasible, but duplicating the existing demo is secondary to giving the research/AI audience a specific instrument to explore.

Measure a small funnel: people trying the demo, starting setup, completing a content edit and producing an adapted portfolio. Manually record volunteered successes and recurring failures. GitHub's free [traffic view](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository) provides a fourteen-day window for visitors/referrers/clones to users with push access; overlapping windows should not be summed. Stars are one discovery signal, not the primary measure of a working tool.

The first pilot target is **three successful first-use/content-edit attempts and two independently adapted outputs**. These are practical goals, not statistical validation or a popularity forecast. Successful users give the next video and release stronger evidence than an expanding feature checklist.
